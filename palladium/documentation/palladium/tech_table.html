Tech Table

The tech table has three tabs. Craft is timed recipes on a 5x5 grid, Modify is for installing modules onto a suit or a device, and Customize is the old accessory slots (casings, color chips). It's all just JSON, so no Java needed. Recipes go in data/<namespace>/recipe/ and modules go in data/<namespace>/argon/suit_modification/.

Crafting recipes

Set "type": "argon:tech_table_crafting". Use pattern and key for a shaped recipe, or ingredients for a shapeless one, not both. A shaped pattern can be any size up to 5x5 and gets found anywhere in the grid.

Setting Type Description Required Fallback Value
pattern List of Strings Up to 5 rows of up to 5 characters, all the same length. A space is an empty slot. false /
key Map What each pattern character is. A plain item, a tag like "#c:ingots/iron", or {"ingredient": ..., "count": 4} if the slot needs a few of them. false /
ingredients List The shapeless version of pattern and key, up to 25 entries. false /
mirror Boolean Lets a shaped pattern match flipped too. false true
tool Tool Something that has to be in the separate tool slot. false none
result Result What you get. true /
name Text component The name shown above the preview, handy for suits. Like {"translate": "recipe.mypack.my_suit"}. false the item's name
time Integer (ticks) How long it takes. 20 ticks is a second, 0 is instant. false 100

When you hit Craft, the table takes the ingredients and starts a timer. It keeps going with the screen closed, and the finished items wait in the output slots until you take them.

Tool

Setting Type Description Required Fallback Value
ingredient Ingredient What has to be in the tool slot. true /
mode "consumed" | "retained" | "damaged" Used up, left alone, or loses durability. false retained
amount Integer How many get used up, or how much durability is lost. false 1

Result

Setting Type Description Required Fallback Value
item Item stack One item, like {"id": "minecraft:diamond", "count": 2}. false /
suit_set Identifier A Palladium suit set, like fsang:marvel/spiderman/iron_mcu. You get every piece of it. Use one of these two, not both. false /

Modules

A module can go on a complete suit in the four suit slots (suits) or on an item in the device slot (items). The file name is its id.

Setting Type Description Required Fallback Value
category "active" | "passive" | "cosmetic" Which column it shows up in. What each one means is up to you. true /
name Text component Skip it and it looks for the translation key suit_modification.<namespace>.<name>. false translation key
description Text component Same, with .description on the end of the key. false translation key
icon Object {"item": "ns:item"} or {"texture": "ns:textures/gui/x.png"} (16x16). false placeholder tile
suits List of Identifiers Suit sets it can go on. false none
items List of Ingredients Items it can go on in the device slot (an item or a tag). The slot only takes items that a module lists here. false none
requirements List Items taken from the player's inventory each time it's installed, like {"ingredient": ..., "count": 3}. false none
consume_requirements Boolean Set to false and they only need to carry the items. false true
prerequisites List of Identifiers Modules that need to be installed first. false none
conflicts List of Identifiers Modules it can't go together with. Only one of the two has to list the other. false none
max_level Integer How many times it can be installed. Every install uses the requirements again. false 1
removal Removal Whether it can be taken back out. false permanent
effects List of Effects What installing does to the item itself. false none
highlight String A body part to outline on the preview: head, body, arms, left_arm, right_arm, legs, left_leg, right_leg. false none
preview_layers List of Identifiers Render layers to show on the preview while it's installed or selected. Good for cosmetics. false none
sort_order Integer Order in its column, lowest first. false 0

Removal

Either "permanent" (the default, no Remove button), "removable", or an object that gives items back: {"mode": "refund", "refund": [{"id": "minecraft:gold_ingot", "count": 1}]}. With levels you get the refund for each level you remove.

Effects

Effects change the item a module is installed on. Each one has a type. They're reapplied for the current level whenever something is installed or removed, so taking everything off puts the item back how it was.

Type Settings What it does
argon:fluid_capacity per_level (mB) Adds capacity to a fluid item like the web shooters, up to the item's own max.
argon:energy_capacity per_level (RF), max Same thing for an item with energy capacity, like the arc reactor.
argon:integer_component component, per_level Sets any whole-number component to per_level times the level.
argon:custom_value key, values, fallback, tooltip Writes a named number onto the item, based on which item you used. More below.

custom_value

Say a module accepts a few different items, and you want the number to depend on which one got used. That's this. key is the name you give the number, values is a list of {"item": ..., "value": 5} (the first used item that matches wins), and fallback is what you get if nothing matches. tooltip is the line the item shows, with %s where the number goes. It can be a translation key or just the text.

Every level adds its own number, so three cores worth 2, 5 and 10 make 17, and removing a level takes the last one off. To use it in a power, use the argon:item_custom_value value (slot, key, fallback). In Java it's CustomValues.total(stack, key, fallback).

Examples

A suit recipe that uses up a catalyst in the tool slot:

{
  "type": "argon:tech_table_crafting",
  "pattern": ["bbbbb", "brrrb", "brsrb", "brrrb", "bbbbb"],
  "key": {
    "b": "palladium:blue_fabric",
    "r": "palladium:red_fabric",
    "s": "palladium:yellow_fabric"
  },
  "tool": { "ingredient": "fsang:beta_molecule_fabric", "mode": "consumed", "amount": 2 },
  "result": { "suit_set": "fsang:dc/superman_absolute" },
  "name": { "translate": "recipe.fsang.superman_absolute" },
  "time": 600
}

A module with three levels that adds capacity to a device:

{
  "icon": { "item": "fsang:module_capacity" },
  "category": "passive",
  "items": ["fsang:web_shooters"],
  "requirements": [ { "ingredient": "fsang:module_capacity", "count": 1 } ],
  "max_level": 3,
  "removal": { "mode": "refund", "refund": [ { "id": "fsang:module_capacity", "count": 1 } ] },
  "effects": [ { "type": "argon:fluid_capacity", "per_level": 500 } ]
}

A number that depends on which core you use:

{
  "category": "passive",
  "items": ["fsang:arc_reactor"],
  "requirements": [
    { "ingredient": ["minecraft:redstone_block", "minecraft:diamond_block", "minecraft:netherite_ingot"], "count": 1 }
  ],
  "max_level": 3,
  "removal": "removable",
  "effects": [ {
    "type": "argon:custom_value",
    "key": "example:core_power",
    "values": [
      { "item": "minecraft:redstone_block", "value": 2 },
      { "item": "minecraft:diamond_block", "value": 5 },
      { "item": "minecraft:netherite_ingot", "value": 10 }
    ],
    "fallback": 1,
    "tooltip": "Core Power: %s"
  } ]
}

Using that number in a power (here it's the reach of a beam, 4 blocks without it):

"core_beam": {
  "type": "argon:energy_beam",
  "beam_renderer": "mypack:core_beam",
  "max_distance": {
    "type": "argon:item_custom_value",
    "slot": "curios:body",
    "key": "example:core_power",
    "fallback": 4
  }
}

And turning an ability on only while a module is installed:

"state": {
  "enabling": {
    "type": "argon:has_suit_modification",
    "modification": "example:reserve_battery"
  }
}

That condition also takes suit, slot (to check a device instead of a suit) and min_level.

Where modules are saved: on the items themselves, not on the player, so they go wherever the item goes. A suit only counts as having a module while every piece has it.
