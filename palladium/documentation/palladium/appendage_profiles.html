Appendage Profiles

Defines the shape, count, attachment points, and idle behavior of a set of procedural appendages (arms, tentacles, tails). Loaded from data/<namespace>/argon/appendage_profiles/*.json and referenced by id, mainly via argon:appendages's own profile setting. Other abilities (argon:appendage_climbing, argon:appendage_attack, ...) control what the appendages actually do. How they visually open and close is chosen by the profile's deployment setting.

Settings

Setting Type Description Required Fallback Value
count Integer (1 - 64) How many appendages this profile defines. true /
segments Integer (1 - 16) Joints per appendage; more gives a smoother bend. false 6
length Decimal (0.1 - 64) Unused - reach is actually set by each attachment point's "offset"/"idle_offset". Still required by the schema. true /
width Decimal (0.01 - 8) Beam thickness, in blocks. false 0.15
solver "rigid" | "articulated" | "curved" | "tentacle" Curve-bending style - see Solver Modes below. false articulated
beam_renderer Identifier Beam renderer id used to draw each segment. true /
attachment_points List of Attachment Point One entry per appendage (see Attachment Point); extra appendages reuse the last entry. true /
idle Idle Settings Idle sway/lag settings - see Idle Settings below. false see Idle Settings
end_model Item Tip item (claw, hand, ...); omit for none. Overridable per appendage. false none
curl_strength Decimal (0 - 1) How much the idle tip curls toward the wearer's front instead of its own offset direction. false 0
end_model_offset [X, Y, Z] Local offset for the tip item (X sideways, Y up, Z outward). Overridable per appendage. false [0.0, 0.0, 0.0]
end_model_scale Decimal (0 - 64) Tip item scale. Overridable per appendage. false 1.0
reach_lag Decimal (0 - 0.95) How much the reach point trails its target - 0 snaps instantly, higher eases into a visible travel motion. false 0.6
deployment "symbiotic" | "mechanical" | Deployment Settings How the appendages visually open and close - either just a style name, or an object with the full tuning. See Deployment below. false "symbiotic" (the original behavior)

Attachment Point

One appendage's attachment point, idle rest direction, and optional tip-model overrides.

Setting Type Description Required Fallback Value
bone String The model part this follows (e.g. body, head, left_arm). true /
offset [X, Y, Z] Local offset from the bone, in blocks. true /
idle_offset [X, Y, Z] Idle reach direction/distance; also biases how other targets bend. false [0.0, 0.0, 0.0]
end_model Item Overrides the profile's tip item for this appendage; omit to inherit it, or set an air-like item for none. false profile's end_model
end_model_offset [X, Y, Z] Overrides the profile's tip offset for this appendage. false profile's end_model_offset
end_model_scale Decimal (0 - 64) Overrides the profile's tip scale for this appendage. false profile's end_model_scale
stored_direction [X, Y, Z] Mechanical deployment only: the direction (same body-local convention as "idle_offset") this appendage is fed out along while it opens, before its joints articulate into the open pose. It does not have to match the open direction - appendages sharing a stored direction nest together along one path until they articulate apart. See Deployment. false direction of "idle_offset" (or "offset" if that is zero)
stored_bends List of Decimal (degrees, -180 - 180) Mechanical deployment only: optional per-joint bend angles of the stored path, so an appendage can be folded up in storage instead of a single straight rod. Entry j bends the stored path at joint j + 1, in the vertical plane containing "stored_direction"; missing entries mean straight. false [] (straight)
segments Integer (1 - 16) Overrides the profile's "segments" for just this appendage, so one profile can mix short and long limbs. Each extends and retracts according to its own segment count. false profile's segments

Idle Settings

Idle sway and movement/rotation lag, set once for the whole profile.

Setting Type Description Required Fallback Value
motion_speed Decimal How quickly the idle sway animation cycles. false 0.2
motion_strength Decimal How far the idle sway displaces the tip, in blocks. false 0.15
spread Decimal Multiplier on "idle_offset"'s length - idle reach distance. false 1.5
movement_lag Decimal (0 - 0.95) How much the attachment origin lags behind the wearer's movement. false 0.3
rotation_lag Decimal (0 - 0.95) Same as "movement_lag", but for facing direction. false 0.4

Deployment

How the appendages visually open and close. Set with the profile's "deployment" setting, either as just a style name ("deployment": "mechanical") or as an object with the settings below. Profiles that don't set it use symbiotic, exactly as before.

Every style runs off one 0-1 timeline: 0 is fully closed, 1 is fully open. argon:appendages steps it toward 1 over its "open_time" ticks when enabled and toward 0 over its "close_time" ticks when disabled (so the durations live on the ability, not here). Closing is therefore the same motion as opening run backwards, and reversing part-way simply continues from wherever the timeline currently is. Once fully open, the normal idle/climbing/attack simulation takes over.

Styles

  • symbiotic (default) - like a living limb growing out of the wearer: the fully-solved curve is revealed along its own length, so the base is always where it will end up and the tip grows outward. Closing retracts it back the same way. Suits tentacles, symbiotes, tails and other biological or magical limbs.

  • mechanical - like a piece of machinery deploying from a housing. Rigid sections telescope out along a stored path first (each keeping its true length - a section is never scaled, only more of it is exposed), and only then do the joints articulate from their stored angles into the open pose. Closing folds the joints back into storage alignment, then retracts the sections toward the root. While opening or closing, the appendage is driven purely by this animation (no physics, idle sway or targets act on it), stays attached to the wearer as they move, and hands over to the normal simulation from the exact open pose. Suits robotic arms, Iron-Spider-style legs, powered armor extensions and other machinery. The closed housing itself is part of your model/render layer - at 0 the appendage draws nothing.

Deployment Settings

The object form. Only "style" matters for symbiotic; everything else tunes the mechanical style.

Setting Type Description Required Fallback Value
style "symbiotic" | "mechanical" Which deployment style to use. false symbiotic
extension_phase Phase Window The part of the timeline where the rigid sections are fed out along their stored paths. Fast, decelerating actuator movement by default. false start 0.0, end 0.65, easing out_cubic
articulation_phase Phase Window The part of the timeline where the joints rotate from their stored angles into the open pose. May overlap the extension phase slightly so the two read as one continuous motion. false start 0.55, end 1.0, easing in_out_sine
sequential_segments Boolean Whether segments emerge one after another from root to tip (telescoping) instead of all extending at once. false true
segment_overlap Decimal (0 - 1) When sequential: how much consecutive segments' extension overlaps. 0 = each waits for the previous to finish, 1 = all move together. false 0.5
extension_hold Decimal (0 - 1) An optional pause, as a fraction of the timeline, between extension finishing and articulation starting - the brief "servo staging" beat. 0 uses the articulation window exactly as configured. false 0.0
articulation_stagger Decimal (-0.95 - 0.95) 0 = every joint articulates together. Toward 1: root joints go first and tip joints follow. Toward -1: tip joints go first (outer joints hinge before inner ones). false 0.0
tip_model "when_open" | "follow" Where the tip item ("end_model") is drawn while not fully open. "when_open": hidden until fully open and gone as soon as it starts closing. "follow": rides the leading edge as the appendage extends and retracts. false "when_open" for symbiotic, "follow" for mechanical

Phase Window

A slice of the 0-1 timeline in which one thing happens, and how that thing's own progress is eased within it.

Setting Type Description Required Fallback Value
start Decimal (0 - 1) Timeline position where this phase begins. false 0.0
end Decimal (0 - 1) Timeline position where this phase finishes. Must be greater than "start". false 1.0
easing Easing The easing curve for this phase. One of: linear, constant, in_sine, out_sine, in_out_sine, in_cubic, out_cubic, in_out_cubic, in_quad, out_quad, in_out_quad, in_quart, out_quart, in_out_quart, in_quint, out_quint, in_out_quint, in_expo, out_expo, in_out_expo, in_circ, out_circ, in_out_circ, in_back, out_back, in_out_back, in_elastic, out_elastic, in_out_elastic, in_bounce, out_bounce, in_out_bounce. Avoid the back/elastic/bounce curves for mechanical motion unless you want overshoot. false linear

Solver Modes

The "solver" setting picks the curve-bending style:

  • rigid - straight line, no bend.

  • articulated - gentle bend biased by "idle_offset"/"curl_strength" - default, for mechanical arms.

  • curved - smoother, sweeping bend.

  • tentacle - loosest, most flowing bend - for tentacles/tails.

Example

A four-armed profile with mechanical claws:

{
  "count": 4,
  "segments": 3,
  "length": 0.1,
  "width": 0.75,
  "solver": "articulated",
  "beam_renderer": "example:appendage_beam",
  "curl_strength": 0.5,
  "end_model": "example:claw",
  "end_model_offset": [0.0, 0.44, 0.15],
  "end_model_scale": 1.0,
  "reach_lag": 0.6,
  "attachment_points": [
    { "bone": "body", "offset": [-0.1, 0.2, 0.1], "idle_offset": [-7.0, -6.0, 1.0] },
    { "bone": "body", "offset": [0.1, 0.2, 0.1], "idle_offset": [7.0, -6.0, 1.0] },
    { "bone": "body", "offset": [-0.1, 0.4, 0.1], "idle_offset": [-7.0, 6.0, 1.0] },
    { "bone": "body", "offset": [0.1, 0.4, 0.1], "idle_offset": [7.0, 6.0, 1.0] }
  ],
  "idle": {
    "motion_speed": 0.25,
    "motion_strength": 0.1,
    "spread": 0.1,
    "movement_lag": 0.25,
    "rotation_lag": 0.45
  }
}

The same idea deployed mechanically: the two right-hand limbs share a stored direction so they emerge nested along one path, then articulate apart; the last limb has more segments than the rest:

{
  "count": 4,
  "segments": 4,
  "length": 1.75,
  "width": 0.5,
  "solver": "curved",
  "beam_renderer": "example:appendage_beam",
  "end_model": "example:claw",
  "deployment": {
    "style": "mechanical",
    "extension_phase":    { "start": 0.0,  "end": 0.65, "easing": "out_cubic" },
    "articulation_phase": { "start": 0.55, "end": 1.0,  "easing": "in_out_sine" },
    "sequential_segments": true,
    "segment_overlap": 0.5,
    "extension_hold": 0.0
  },
  "attachment_points": [
    { "bone": "body", "offset": [-0.1, 0.2, 0.1], "idle_offset": [-7.0, 6.0, 1.0], "stored_direction": [-1.0, 1.1, 0.0] },
    { "bone": "body", "offset": [0.1, 0.2, 0.1],  "idle_offset": [7.0, 6.0, 1.0],  "stored_direction": [1.0, 1.0, 0.0] },
    { "bone": "body", "offset": [0.1, 0.2, 0.1],  "idle_offset": [7.0, -2.0, 1.0], "stored_direction": [1.0, 1.0, 0.0] },
    { "bone": "body", "offset": [-0.1, 0.2, 0.1], "idle_offset": [-7.0, -6.0, 1.0], "stored_direction": [-1.0, -0.3, 0.0], "segments": 6 }
  ]
}

And the minimal way to pick a style, leaving everything else at its defaults:

"deployment": "symbiotic"
"deployment": "mechanical"
